Architecture Pillars

Six pillars that keep MoE inference deterministic

Each pillar is a first-class subsystem. The asymmetric bento below shows how they compose into a single sovereign fabric.

PILLAR 01 · RDMA

RDMA Tensor Sharding

Tensors split across GPU nodes and transferred over RDMA fabric without staging through the host CPU. Reads bypass the copy path for microsecond shard availability.

PILLAR 02 · SPEC

Speculative Tree Verification

A draft model proposes candidate token trees; the target validates in one pass and accepts the valid prefix, discarding invalid branches.

PILLAR 03 · NVMe

NVMe Page-Cache Pinning

Hot page-cache entries pinned to remote NVMe namespaces stay resident, so repeated expert lookups hit pinned pages instead of cold reads.

PILLAR 04 · KV

Zero-Copy KV Ring

Shard metadata and KV state stay resident in pinned NVMe pages, resolved against the fabric rather than a disk round-trip.

PILLAR 05 · QUANT

Deterministic Quantization

Fixed bits-per-weight quantization guarantees reproducible outputs so audit trails are verifiable across enclaves.

PILLAR 06 · ENCLAVE

Hardware Enclave Isolation

Model assets, KV state, and telemetry never leave the enclave boundary. The fabric is a private, air-gappable cluster with enclave-per-node isolation.

Engineering FAQ

Deep answers for the engineering team

RDMA tensor sharding splits model tensors across GPU nodes and transfers them over RDMA fabric without staging through the host CPU. Because reads bypass the copy path, shard fetches complete in microseconds. The zero-copy KV ring keeps shard metadata resident in pinned NVMe pages, so a token request resolves against the fabric rather than a disk round-trip. Net effect: sub-millisecond shard availability for MoE expert routing.

Speculative tree verification lets a small draft model propose candidate token trees ahead of the target model. The target validates the tree in one pass and accepts the valid prefix, discarding invalid branches. MoE models benefit because expert selection is predictable per prompt, so the draft can pre-warm the experts a tree is likely to need. This cuts effective per-token latency without lowering output fidelity.

NVMe-over-Fabrics exposes remote NVMe namespaces as block devices. VORTEX pins hot page-cache entries directly to those namespaces and keeps them resident, so repeated expert lookups hit pinned pages instead of cold reads. Pinning is coordinated by the KV ring, which tracks which pages are hot across the cluster and evicts cold ones deterministically.

Yes. VORTEX runs entirely inside hardware enclaves with enclave-per-node isolation. Model assets, KV state, and telemetry never leave the enclave boundary. There is no external network dependency for inference; the fabric is a private, air-gappable cluster. Deterministic quantization guarantees reproducible outputs so audit trails are verifiable.

Edge Node 8GB suits small expert sets and low batch concurrency for on-prem edge inference. Workstation 12GB handles mid-sized MoE active parameter sets with moderate batch sizes. Rack Pod 8xGPU is for high-concurrency production inference where throughput and deterministic latency matter.
